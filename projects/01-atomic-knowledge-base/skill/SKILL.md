# Shulex Atomic Knowledge Base Skill (客服知识库原子化拆解)

本 Skill 用于解决当前智能客服与 AI Agent 落地中最普遍的痛点：**“直接喂几十万字说明书给大模型，导致 AI 答非所问、政策冲突、严重幻觉（胡说八道）”**。

通过本 Skill，Agent 可以将任何凌乱、冗长、非结构化的电商或企业客服资料，系统性清洗、拆解并输出为工业级的**四层原子化结构表**。

---

## 核心方法论：四层原子化金字塔 (The 4-Layer Atomic Framework)

```
       ┌────────────────────────┐
       │  Layer 4: 动作闭环指令  │  -> 带明确 Action、表单索要、ERP联动
       ├────────────────────────┤
       │  Layer 3: 买家口语词库  │  -> 补充 3-5 句真实大白话同义表达
       ├────────────────────────┤
       │  Layer 2: 产品参数原子  │  -> 表格化数据、兼容清单、故障排查
       ├────────────────────────┤
       │  Layer 1: 基础政策规矩  │  -> 全店统一、绝对无歧义、底线红线
       └────────────────────────┘
```

### 1. 表 1：基础政策规矩表（底线红线）
* **定位**：退换货时效、运费承担方、质保范围、发票规则等全店通用底线。
* **准则**：每一条必须是一句明确、无二义性的结论，全店只保留唯一版本，杜绝在多文档中出现口径冲突。

### 2. 表 2：产品与参数原子表（事实真理）
* **定位**：尺寸、电压、接口、材质、官方兼容清单、明确不兼容清单、故障代码。
* **准则**：严禁大段落描述，全部转为结构化键值对（Key-Value）或表格。AI 查表即可得出准确事实，从源头消灭参数幻觉。

### 3. 表 3：买家大白话扩展表（语义桥接）
* **定位**：解决“官方术语 vs 买家大白话”之间的语义鸿沟。
* **准则**：每个核心场景（如“无法开机”），必须补充至少 3~5 句买家真实提问（如“灯不亮”、“按了没反应”、“冒黑烟了”、“怎么死机了”）。

### 4. 表 4：决策与行动指令表（闭环执行）
* **定位**：让 AI 告别只动嘴皮子的“复读机”，成为真正能帮用户办事的数字员工。
* **准则**：定义触发条件（L1 自动 / L2 人工）、必须索要的凭据（单号/照片）、以及联动的后台动作（推送补发、工单流转、小额补偿）。

## Agent 执行指令与工作流 (Transformation Pipeline)

当用户提供一段未整理的客服文档、说明书或 FAQ，并请求整理知识库时，Agent 必须按以下 4 步执行：

### Step 1: 冲突检测与版本清洗 (Deconfliction)
* 扫描用户文本中是否存在前后矛盾的规则（例如“第一段写7天无理由退货运费买家出，后面又写活动期间包邮退”）；
* 主动向用户指出冲突，并要求确认唯一的标准口径。

### Step 2: 拆解入表 (Atomization)
* 将文档内容分别归类到 4 张原子表中，严禁大段文本复制，必须做摘要与结构化表格提炼。

### Step 3: 大白话同义句扩充 (Colloquial Expansion)
* 针对提取出的核心问题，结合真实电商买家高频口语，自动补充 3~5 条自然口语变体。

### Step 4: 注入行动指令 (Action Binding)
* 检查每一个售后或咨询场景的回复结尾，是否带有明确的下一步引导或动作触发条件。
